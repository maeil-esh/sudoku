# SPEC — 스도쿠 (Android, Google Play)

문서 버전: 0.1 (2026-11-16) · 상태: 초안 확정 대기 · 규칙 요약은 `/CLAUDE.md`

## 1. 목표와 비목표

**목표**
- 오프라인에서 끊김 없이 동작하는 깔끔한 스도쿠 앱을 Google Play에 배포한다.
- 프리미엄(일회성 결제)을 판매하고, 초청 사용자 **최대 500명**에게 Google Play 프로모 코드로 무료 제공한다.

**비목표 (1차 릴리스에서 하지 않음)**
광고, 자체 서버/계정/로그인, 클라우드 동기화, 온라인 랭킹·멀티플레이, 변형 스도쿠, 위젯, 분석/크래시 수집 SDK, 다국어(한국어만).

```
:app
 ├─ ui/            Compose 화면, 컴포넌트, Theme(디자인 토큰)
 │   ├─ home/ game/ premium/ stats/ settings/

 │   ├─ model/     Board, Cell, Difficulty, Move, GameState
 │   ├─ solver/    Solver(유일해 카운트), TechniqueSolver(사람 기법 기반 난이도 평가)

```
- 패키지 루트(applicationId)는 **사용자 확정 필요**. 임시값 `com.uk2solutions.sudoku`. 출시 후 변경 불가이므로 M0 시작 전에 확인한다.
- DI: Hilt. 상태: ViewModel + `StateFlow<UiState>`, 이벤트는 단방향.
- `domain`은 JVM 단위 테스트만으로 검증 가능해야 한다.

## 5. 도메인 명세

### 5.1 보드/상태
- 칸 값 0–9(0=빈칸), `given: Boolean`, 메모는 9비트 마스크.
- 직렬화: givens 81자 문자열, 정답 81자 문자열, 현재 값 81자 + 메모 마스크 배열.
- 입력 규칙: 숫자 패드로 선택 칸에 입력. 메모 모드면 메모 토글. `given` 칸은 수정 불가.
- 오류 판정: **정답 비교**(해와 다르면 오류) 또는 **규칙 충돌**(같은 행/열/박스 중복) — 설정 "오류 즉시 표시" ON일 때만 표시. 목업은 충돌 표시(해당 칸 빨강 + 중복 칸 옅은 빨강 배경). 색만으로 구분하지 않도록 오류 칸은 굵기도 함께 변경.
- 실수: 정답과 다른 값을 입력할 때마다 +1. 제한(기본 3, 설정으로 끔) 도달 시 다이얼로그: 새 게임 / 제한 없이 계속.
- 되돌리기: 입력·지우기·메모 변경을 이동 단위로 스택 저장(저장 시 함께 직렬화, 최대 200).
- 하이라이트: 선택 칸의 행·열·박스는 옅게, 선택 칸은 진하게, 같은 숫자 칸은 중간 톤(설정 가능).
- 메모 자동 삭제: 숫자 확정 시 같은 행·열·박스의 해당 메모 제거(설정 기본 ON).
- 숫자 패드 "남은 개수" = 9 − 현재 보드에 놓인 해당 숫자 수. 0이면 "완료"로 비활성.
- 완료: 모든 칸이 정답과 일치하면 완료 처리, 타이머 정지, 기록 저장.

### 5.2 퍼즐 생성 (온디바이스)
1. 무작위 완성 격자 생성(역추적, 시드 기반 PRNG. `java.util.Random` 대신 자체 구현해 기기·OS 간 결정성 보장).
2. 칸을 (중심 대칭 우선) 제거하며 **해 개수 카운트(2개 발견 시 중단)**로 유일해 유지.
3. `TechniqueSolver`로 사람 기법만으로 풀어 난이도 등급 산출. 목표 난이도와 다르면 폐기·재시도.
4. 백그라운드에서 난이도별 풀(Pool)을 미리 채워 Room에 저장(목표: 난이도당 5판 이상). 풀이 비면 즉시 생성.

| 난이도 | 필요한 기법(상한) | 단서 수 가이드 |
|---|---|---|
| 쉬움 | 단일 후보, 숨은 단일 | 36–40 |
| 보통 | + 포인팅/박스-라인 축소, 노출 쌍 | 30–35 |
| 어려움 | + 숨은 쌍/삼중, 노출 삼중 | 27–30 |
| 전문가 | + X-윙, Y-윙, 스워드피시 | 24–27 |
| 악마 | 위 기법 + 추측 필요 가능(또는 기법 한도 초과) | 22–25 |

단서 수는 가이드일 뿐 **판정 기준은 기법 등급**이다. 생성 시간 목표: 쉬움·보통은 중급 기기에서 평균 500ms 이하(풀 캐시로 사용자 체감 0). 전문가·악마는 풀 캐시 전제.

### 5.3 오늘의 도전
- 시드 = `yyyyMMdd`(기기 로컬 날짜) + 앱 고정 솔트 → 같은 날 모든 사용자에게 같은 퍼즐. 난이도는 요일별 로테이션(예: 어려움 고정으로 시작, 추후 조정).
- 하루 한 판: 완료/진행 상태 저장. 완료 시 연속 일수(스트릭) 갱신. 날짜가 바뀌면 새 퍼즐.
- 기기 날짜 조작은 막지 않는다(개인용 앱, 랭킹 없음).

### 5.4 힌트
- 1단계: 다음에 풀 수 있는 칸과 사용 기법 이름을 표시(칸 강조). 2단계(한 번 더 누름): 값을 채움.
- 무료: 하루 3회(로컬 날짜 기준 초기화). 프리미엄: 무제한. 힌트로 채운 칸은 "힌트 사용" 기록, 기록 갱신에서 제외하지는 않음(단순화).

### 5.5 저장/복구
- 진행 중 게임은 1개만 유지(오늘의 도전은 별도 1개). 이동 후 500ms 디바운스 자동 저장 + `onStop` 즉시 저장.
- 프로세스 종료 후 재실행 시 홈의 "이어하기"로 복구. 타이머는 경과 시간만 저장(백그라운드 시간 제외).

## 6. 디자인

### 6.1 토큰 (목업 값)
| 토큰 | 값 | 용도 |
|---|---|---|
| background | `#F6F4EF` | 앱 배경 |
| surface | `#FFFFFF` | 카드, 보드, 버튼 |
| onSurface (ink) | `#1F2430` | 본문, 주어진 숫자, 굵은 격자선 |
| muted | `#5B6272` | 보조 텍스트 (배경 위 대비 4.5:1 이상) |
| line | `#D9D5CA` | 테두리, 얇은 격자선 |
| accent | `#2F4BCB` | 주 버튼, 내가 입력한 숫자, 선택 강조 |
| accentSoft | `#E4E9FB` | 보조 버튼 배경, 메모 켜짐 |
| cellPeer | `#ECEFF9` | 선택 칸의 행·열·박스 |
| cellSelected | `#CFD8F8` | 선택 칸 |
| error | `#B3261E` / 배경 `#FBE3E0` | 오류 숫자 / 오류 칸 배경 |

- 격자: 박스 경계 2dp(ink), 칸 경계 1dp(line). 보드 바깥 2dp(ink).
- 숫자: 칸 22sp, 주어진 숫자 SemiBold(ink), 입력한 숫자 Medium(accent), 메모 10sp(muted, 3×3 배치).
- 숫자 패드: 5열 2행(1–5 / 6–9 + 지우기), 높이 56dp, 숫자 24sp + "남은 n" 11sp.
- 화면 여백 20dp(게임 화면 15dp), 카드 반경 20dp, 버튼 반경 12–16dp, 터치 타깃 ≥ 48dp.
- 글꼴: 시스템 기본 한글 폰트(번들 폰트 없음). 목업의 Noto Sans KR은 예시.
- 다크 테마 값은 M5에서 같은 역할 이름으로 정의(배경 어두운 중성색, accent는 밝은 톤으로 조정, 대비 4.5:1 확인).

### 6.2 상호작용 규칙
- 칸 탭 = 선택. 선택 칸에서 숫자 탭 = 입력(메모 켜짐이면 메모 토글).
- 잠금 난이도(전문가·악마) 탭 → S3로 이동. 잠금은 숨기지 않고 보이게 둔다.
- 일시정지 시 보드는 가려서 타이머 꼼수 방지.
- 햅틱: 입력 약한 진동, 오류 강한 진동 (설정에서 끔).
- 뒤로가기: 게임 중 → 자동 저장 후 홈. 화면 회전은 세로 고정(1차).

## 7. 결제와 프로모 코드

### 7.1 상품
| 항목 | 값 |
|---|---|
| 상품 ID | `premium_lifetime` |
| 유형 | 일회성 인앱 상품(비소모성) |
| 가격 | Play Console에서 사용자가 설정. 앱은 `ProductDetails`의 가격 문자열을 그대로 표시(하드코딩 금지) |

### 7.2 앱 동작
1. **앱 시작/포그라운드 복귀(onResume)마다** `queryPurchasesAsync(INAPP)`로 보유 구매를 조회한다. (사용자가 Play 스토어에서 코드를 먼저 적용한 경우도 이 경로로 반영된다.)
2. `PurchasesUpdatedListener`로 앱 안에서 발생한 구매·프로모 상환을 받는다.
3. `PURCHASED` 상태이며 상품 ID가 `premium_lifetime`이면 프리미엄 ON. **`PENDING`은 부여하지 않는다.**
4. 구매를 받으면 **반드시 acknowledge**한다(미승인 구매는 일정 기간 후 자동 환불됨. 기한은 공식 문서에서 확인).
5. 캐시: DataStore에 `premiumCached`, `lastVerifiedAt` 저장. 오프라인이면 캐시를 신뢰한다. **온라인에서 조회 응답이 성공했는데 구매가 없을 때만** 프리미엄을 해제한다(조회 실패 시 해제 금지).
6. 구매 복원 버튼 = 위 조회를 수동 실행.

### 7.3 초청코드 UX (S3)
- "적용" 탭 → 입력값 trim/공백 제거 → Play의 코드 상환 화면으로 이동(상환은 Google Play가 처리). 구체적 URL/인텐트 형식은 **공식 문서 "Promo codes" / "In-app promotions"에서 현재 방식을 확인해 구현**하고 `docs/DECISIONS.md`에 근거를 남긴다.
- 앱 복귀 시 7.2의 조회를 실행: 프리미엄이 켜지면 "프리미엄이 적용되었습니다" 안내, 아니면 "코드 적용이 확인되지 않았습니다. Play 스토어에서 상환 후 다시 시도해 주세요" 안내.
- 앱은 코드 유효성을 직접 판단하지 않는다. 코드는 로그·분석·저장소에 남기지 않는다.
- 사용자가 Play 스토어 앱의 "코드 사용"으로 먼저 상환해도 동일하게 동작해야 한다.

### 7.4 프로모 코드 운영 제약 (공식 문서 기준, 2026-11 확인)
- 일회성 상품 프로모 코드는 앱당 분기별 최대 500개(앱 유료 코드 등과 합산).
- 프로모션 생성 후 코드 수 변경 불가. 분기 내 미사용 코드는 다음 분기로 이월되지 않음.
- 커스텀(다회용) 코드는 구독 전용이므로 이 구조에서 사용하지 않음.
- 한도(500)를 넘겨야 하면 BACKLOG의 "자체 코드 서버" 안을 사용자와 협의.

### 7.5 테스트
- `BillingGateway` Fake로 시나리오 단위 테스트: 미구매 / 구매 완료 / PENDING / 오프라인 캐시 / 조회 실패 시 유지 / 환불(구매 사라짐) 시 해제 / acknowledge 호출.
- 실제 Play 연동은 사용자가 내부 테스트 트랙 + 라이선스 테스터로 검증(§10). 프로모 코드 테스트 방법은 공식 "Test promo codes" 문서를 따른다.

## 8. 데이터 모델

**Room `game`**: `id`, `mode`(NORMAL/DAILY), `difficulty`, `givens`(81), `solution`(81), `values`(81), `notes`(81개 마스크), `elapsedMs`, `mistakes`, `hintsUsed`, `undoStack`(직렬화), `status`(IN_PROGRESS/COMPLETED/ABANDONED), `dailyDate`(nullable), `startedAt`, `finishedAt`.
**Room `puzzle_pool`**: `id`, `difficulty`, `givens`, `solution`, `createdAt`.
**기록 집계**: `game`의 COMPLETED 행에서 쿼리(별도 집계 테이블 없음).
**DataStore**: 테마, 소리, 진동, 오류 즉시 표시, 실수 제한 사용/횟수, 같은 숫자 강조, 메모 자동 삭제, `premiumCached`, `lastVerifiedAt`, `hintsUsedToday`, `hintsDate`.
