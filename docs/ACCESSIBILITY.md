# 접근성 점검 (M5)

## 자동 점검 (테스트로 고정)
| 항목 | 방법 | 결과 |
|---|---|---|
| 글자 4.5:1 / 비텍스트 3:1 대비 | `ContrastTest` — 테마 8종(블루·그린·오렌지·퍼플 × 라이트·다크) × 20개 조합. 표: `CONTRAST_REPORT.md` | **160/160 통과** (미달 9곳은 다크 선택·같은 숫자 칸 배경을 어둡게 고쳐 해결) |
| 누를 수 있는 모든 요소에 읽을 이름 | `SemanticsTest` — 게임·홈·기록·설정·프리미엄·도전장 화면의 병합된 접근성 트리 | 통과. **숫자 패드 키 9개가 TalkBack으로 눌리지 않던 결함을 발견·수정**(부모의 `clearAndSetSemantics`가 클릭 동작까지 지움) |
| 글자 크기 200% | 스크린샷 `33~35_*_fontscale_200.png` | 칸 안 글자는 상한(1.3배, 메모는 고정), 홈 버튼은 세로로 쌓기, 정보 줄은 양 끝 정렬로 겹침 해결 |
| 색만으로 의미 전달 금지 | 코드 검토 | 오류 칸은 빨강 + 굵기, 선택 칸은 색 + 테두리, 잠금은 색 + 아이콘 + 설명 |
| 아이콘 버튼 contentDescription | `SemanticsTest` + 코드 검토 | 뒤로가기·일시정지·잠금 아이콘 모두 설명 있음 |
| 점수 변화 알림 | 코드 검토 | `liveRegion = Polite`로 읽힘 |

## 기준과 다른 점 (의도적, 근거 포함)
| 항목 | 기준 | 현재 | 판단 |
|---|---|---|---|
| 숫자 키 너비 | 터치 타깃 ≥ 48dp | 약 38dp × 높이 64dp | 한 줄 9키는 참고 앱 구성(사용자 요청)이며 화면 폭상 불가피. WCAG 2.5.8(AA, 최소 24px)은 충족. 높이로 보완. 추후 설정에서 2줄 배치 옵션을 검토 |
| 보드 칸 | ≥ 48dp | 약 40dp | 9×9 격자는 폭상 불가피. 칸 전체가 눌림 대상이고 선택 시 행·열·박스가 강조됨 |
| 얇은 격자선 | 비텍스트 3:1 | line 색은 배경 대비 낮음 | 박스 구분은 굵은 선(ink, 3:1 이상)으로 전달하고, 얇은 선은 보조 |

## TalkBack 수동 점검표 (실기기에서 한 번 해 주세요)
1. 홈에서 오른쪽으로 쓸며 "프리미엄 → 이어하기 → 오늘의 도전 → 새 게임 난이도 → 도전장 받기 → 전문가(잠김)"가 순서대로 읽히는지
2. 새 게임 → 칸을 탐색하면 "3행 4열, 7" / "…, 주어진 숫자" / "…, 규칙 충돌"처럼 읽히는지
3. 칸 선택 → 숫자 키("7, 남은 개수 4") 더블탭으로 입력되는지, 틀린 숫자 입력 후 안내 막대의 "취소"가 읽히고 동작하는지
4. 일시정지 → 보드가 가려지고 "계속"/"나가기"가 읽히는지
5. 완료 창에서 결과·버튼이 읽히는지, 설정의 스위치가 "켜짐/꺼짐"으로 읽히는지
