- 색 토큰 값 조정(역할 이름은 SPEC §6.1 유지): background `#F4F6FB`(차가운 톤), line `#D5DAE6`, cellPeer `#ECEEF3`(회색), cellSame `#BFD3FA`, cellSelected `#CFDCFB`(+accent 테두리 2dp). 사용자 입력 숫자(accent) 대비를 4.5:1 부근으로 유지하도록 강조색을 연하게 잡았다.
- 다크 테마 값을 같은 역할 이름으로 추가(`DarkSudokuColors`). 설정에서 시스템/라이트/다크 선택.
- 숫자 패드를 5열 2행에서 **한 줄 9칸**으로 변경(참고 화면). 칸 너비가 약 38dp로 SPEC의 터치 타깃 48dp보다 좁다. 높이는 64dp로 보완. 접근성 점검(M5)에서 재검토.
- 점수는 저장하지 않고 현재 상태로 계산한다(`Scoring`): (맞게 채운 칸×10 + 새로 완성한 줄·박스×50 − 실수×30 − 힌트×10) × 난이도 배수. 지우고 다시 넣어 점수를 불리는 꼼수를 막는다.
- 참고 화면에 있어도 넣지 않은 것: 광고, 알림, 언어, SNS 링크, 자동완료, 라이팅 모드, 애니메이션 스코어링, 스마트 힌트 토글(SPEC 비목표 또는 범위 밖). 필요하면 BACKLOG로.
- 도구 아이콘은 아이콘 라이브러리 대신 문자(↶ ⌫ ✎ 💡)를 사용(앱 용량·단순함). 기기별 글꼴에 따라 모양이 다를 수 있어 M5에서 벡터 아이콘으로 교체 검토.

## 2026-11-16 범위 변경 (사용자 요청)
- **다국어**: SPEC §1 비목표("한국어만")를 변경. 1차 지원 언어: 한국어, English, 日本語, Español, Português(Brasil), Русский, Deutsch, Français. 2차 후보: 중국어 간체·번체, 힌디어, 인도네시아어, 태국어, 베트남어, 튀르키예어. 아랍어(RTL)는 별도.
  - 앱 내 언어 선택은 `AppCompatDelegate.setApplicationLocales` 사용(Android 13+ 시스템 앱별 언어 설정과 연동, `locales_config.xml`). 번역은 초안이므로 출시 전 원어민 검수 필요. 새 문자열은 모든 언어 파일에 추가해야 린트(MissingTranslation)가 통과한다.
  - Play 스토어 등록 문구(제목·설명)는 앱 내 번역과 별도로 언어별 작성 필요.
- **알림**: 오늘의 도전 리마인더(로컬 알림, WorkManager 주기 작업). 서버·푸시 서비스 없음, 분석 SDK 아님. 기본 꺼짐, Android 13+는 켤 때 알림 권한 요청. 오늘 이미 완료했으면 보내지 않음. 정확한 시각은 보장되지 않음(절전 모드 등).
- **점수 애니메이션**: 칸을 채울 때 +N/−N이 칸 위로 떠오름(설정에서 끔).
- **스크린샷**: `ScreenshotTest`(Robolectric)로 설치 없이 `docs/screens/`에 PNG 생성. 릴리스 변형 테스트에서는 제외. (네트워크: Robolectric 네이티브 jar 때문에 `gcp.mirrors.maven.org` 허용 필요)
- **기본 언어를 영어로 변경**: `values/`(기본)=English, 한국어는 `values-ko/`. 번역이 없는 언어를 쓰는 폰은 영어가 나온다(한국어 폰은 그대로 한국어). 새 문자열은 기본(영어)에 먼저 추가하고 모든 언어 파일에 번역을 넣는다.

## 2026-11-16 M4 프리미엄 (공식 문서 확인 근거)
- **Billing Library 9.1.0** (developer.android.com/google/play/billing/integrate 확인 시점의 최신 안정판). `billing-ktx`는 더 새로운 Kotlin(메타데이터 2.3)으로 빌드되어 현재 Kotlin 2.0.21에서 컴파일 불가 → Java 코어 `billing:9.1.0`을 쓰고 콜백을 코루틴으로 감쌌다. Kotlin을 올리면 ktx로 바꿀 수 있다.
- **승인(acknowledge)**: 3일 내 승인하지 않으면 자동 환불(integrate 문서). 부여 대상 구매는 항상 acknowledge, 같은 세션에서 중복 호출 방지.
- **PENDING**: 일회성 상품은 `enablePendingPurchases(enableOneTimeProducts)` 필수. PENDING → PURCHASED가 될 때만 프리미엄 부여.
- **앱 밖 상환 감지**: `queryPurchasesAsync`를 앱 시작/onResume마다, 그리고 `PurchasesUpdatedListener`로 감지(integrate 문서 "Detect and process purchases").
- **프로모 코드(promo 문서)**: 일회용 코드는 Play 스토어 또는 앱 안 결제 화면의 "상환"에서 사용. 앱에서는 딥링크 `https://play.google.com/redeem?code=<코드>`로 Play 상환 화면을 연다(Play 앱 패키지 `com.android.vending`을 우선 지정, 없으면 브라우저). 일회성 상품 코드는 앱당 분기 500개, 생성 후 수 변경 불가, 미사용분 이월 없음.
- **코드 취급**: 입력값은 공백 제거 후 URL 인코딩만 하고, 화면 상태(`remember`, 저장 안 함)에만 둔다. 로그·DataStore·Room에 저장하지 않는다. 유효성은 Play가 판단.
- **판정 규칙**: PURCHASED + `premium_lifetime`만 부여, 조회 성공 + 구매 없음일 때만 해제(환불), 조회 실패 시 캐시 유지. 캐시는 DataStore `premiumCached`/`lastVerifiedAt`.
- **잠금 제어**: `Entitlement` 한 곳(전문가·악마 잠금, 힌트 무제한, 상세 통계, 추가 컬러 테마). 경계를 바꾸면 이 파일만 수정.
- **추가 컬러 테마 3종**(그린·오렌지·퍼플, 라이트/다크 각각): 사용자 입력 숫자(accent)와 같은 숫자 강조색(cellSame) 대비를 4.5:1 부근으로 유지하는 연한 톤.
- **상세 통계**: 최근 7일 일별 완료 수, 난이도별 완료 비율(프리미엄 전용).
- **알려진 공백**: 전문가·악마 난이도는 기법(X-윙, Y-윙, 스워드피시 등)이 아직 없어 프리미엄 사용자에게도 "준비 중"이다. 프리미엄 판매 전에 구현해야 한다(BACKLOG).
- **2차 언어**: 중국어 간체(zh-CN)·번체(zh-TW), 힌디어, 인도네시아어(`values-in`, 태그 `id`), 태국어, 베트남어, 튀르키예어 추가(총 15개 언어). 번역은 초안, 원어민 검수 필요.

## 2026-11-17 힌트를 "단계별 설명"으로 개편 (사용자 제안: 참고 화면의 스포트라이트 방식)
- 힌트 버튼 → 하단 카드가 열리고, 보드는 **관련 칸만 밝게 남기고 나머지는 어둡게** 한다. 대상 칸은 파란 칸+테두리.
  - 단일 후보(3단계): ① 대상 칸의 행·열·박스 강조 ② 그 안에 이미 있는 숫자들(후보를 지우는 칸 강조)을 보여 주고 "남는 숫자는 하나" ③ 정답 미리보기(칸에 파란 숫자) + **채우기**
  - 숨은 단일(3단계): ① 그 숫자가 들어갈 곳이 하나뿐인 행/열/박스 강조 ② 다른 빈칸마다 그 숫자를 막고 있는 칸(파란 칸) 표시 ③ 정답 + 채우기
  - 추론(2단계): 칸과 주변 → 정답
  - 카드의 단계 점, "다음", 닫기(X). 닫으면 입력은 하지 않고, 하루 힌트 횟수는 힌트를 연 시점에 1회 소모(기존 규칙 유지).
- 계산은 순수 Kotlin(`Hints.plan`)이고 단위 테스트로 검증한다: 단일 후보는 "8개 숫자 제외 → 1개 남음", 숨은 단일은 "단위 안의 모든 다른 빈칸에 막는 칸이 있음".
- 설명 문장은 숫자 뒤 조사(이/가, 은/는)를 피하는 표현으로 썼다(한국어). 15개 언어 번역 추가(초안).
- 이 방식은 "어떻게 푸는지"를 가르치므로 SPEC §5.4의 "다음에 풀 수 있는 칸과 기법 이름 표시 → 값 채움"을 확장한 것이다.

## 2026-11-17 트레이닝 기능 (사용자 요청: 힌트 설명 방식을 응용해 기본부터 고수 단계까지 가르치는 기능)
- **연습 탭(4번째 탭)**: 레슨 12개 — 규칙, 단일 후보, 숨은 단일, 포인팅, 박스-라인 축소, 노출 쌍, 숨은 쌍, 노출 삼중, 숨은 삼중, X-윙, Y-윙, 스워드피시. 묶음: 기초·초급·중급·고수.
- **레슨 흐름**: 소개 → 시연 2단계(패턴 강조 → 결과: 지울 후보를 빨강으로, 단일은 정답 미리보기) → 연습 문제 3개(숫자 고르기 / 칸 고르기 / 지울 수 있는 칸 모두 고르기) → 결과(별 0~3, 최고 점수 저장).
- **기법 엔진**(`domain/technique`, 순수 Kotlin): 11개 기법 탐색기가 "무엇을 채우고/지울 수 있는지"를 계산한다. 검증: 퍼즐 250개를 단계별로 풀며 **정답을 지우거나 틀린 값을 채운 경우 0건**, 11개 기법 모두 실제로 쓰임, 쓸모 없는 추론 없음.
- **예제 탐색**(`TrainingExamples`): 그 기법이 "정말 필요한 순간"(더 단순한 기법을 모두 쓰고 막힌 상태)을 퍼즐에서 찾는다. 같은 입력이면 같은 예제. 전 레슨 예제 4개를 찾는 데 가장 오래 걸리는 레슨(스워드피시) ≈ 1초(JVM)이므로 백그라운드에서 준비한다. 기법 등급 제약이 없는 "유일해 전용" 퍼즐 생성(`generateUnique`)을 추가.
- **무료/프리미엄 경계(초안)**: 규칙~노출 쌍(5개)은 무료, 숨은 쌍 이후(중급·고수 7개)는 프리미엄. 경계는 `Lessons`의 `premium` 값만 바꾸면 된다. 프리미엄 혜택 목록에 "트레이닝 전체 레슨" 추가. **→ 사용자 확인 필요(SPEC §2 표 변경)**.
- **번역**: 트레이닝 문장 91개는 영어(기본)·한국어만 준비했고 나머지 13개 언어는 영어로 표시된다(`values/training.xml`에 `tools:ignore="MissingTranslation"`). 번역 작업은 BACKLOG.
- **저장**: 레슨별 최고 점수만 기기에 저장(DataStore `trainingScores`). 개인정보 처리방침에 반영.
- 기법 엔진은 전문가·악마 난이도 생성(등급 4 이상 판정)에도 재사용할 수 있다(BACKLOG).
